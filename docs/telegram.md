# Подключение Telegram

Рабочая ветка — `codex/platform-telegram`. Финансовая логика и API остаются общими
с браузерной версией. Токен бота сам по себе не подключает Telegram-вход и не
публикует приложение.

## Локальная настройка бота

1. Если токен попал в чат, исходники или другие доступные места, перевыпустить
   его в официальном [BotFather](https://t.me/BotFather): `/revoke`, выбрать бота
   и получить новый токен по подсказкам BotFather.
2. В Windows PowerShell 5.1 или PowerShell 7 из корня репозитория выполнить:

   ```powershell
   ./scripts/configure-telegram.ps1
   ```

3. Ввести новый токен в скрытом приглашении. В чат и исходники его вставлять не нужно.

Скрипт обращается только к `https://api.telegram.org`, проверяет бота методом
[getMe](https://core.telegram.org/bots/api#getme) и сохраняет `Telegram:BotToken`
в .NET User Secrets проекта Finance.Api. JSON передаётся CLI через stdin;
токен не нужен в аргументах командной строки. Скрипт показывает только username
бота и не печатает ошибки HTTP с URL, содержащим секрет. Настройки других
секретов API сохраняются.

[.NET User Secrets](https://learn.microsoft.com/aspnet/core/security/app-secrets?view=aspnetcore-10.0)
находятся вне репозитория, но не шифруются: это средство локальной разработки.
На хостинге токен будет задаваться секретной переменной `Telegram__BotToken`.
Не использовать `dotnet user-secrets list` для скриншотов или вывода в чат.

Скрипт проверяет доступ к Bot API. Он не отправляет сообщения, не меняет меню
бота и не делает приложение доступным из Telegram.

## Вход и общий аккаунт

Telegram использует существующий подтверждённый email-аккаунт. При первом запуске
нужно один раз войти по email и паролю; после привязки следующие запуски открывают
ту же историю автоматически. Новый пользователь может зарегистрироваться и
подтвердить email обычным способом, затем вернуться в Mini App для привязки.
Отдельные финансовые пользователи и фиктивные email не создаются.

Путь запроса: Telegram SDK → `POST /api/auth/telegram/login` с исходным `initData`
→ HMAC-SHA256 и проверка `auth_date` (10 минут, допуск будущего времени 30 секунд)
→ поиск серверной привязки → access JWT и вращаемый refresh token. Если привязки
ещё нет, интерфейс запрашивает email/пароль и вызывает `POST /api/auth/telegram/link`.
Backend повторно проверяет подпись и пароль, затем атомарно создаёт привязку и сессию.
Переданные клиентом id, username, email из профиля Telegram и `initDataUnsafe`
не используются как самостоятельное доказательство личности.

Токены Telegram находятся в памяти клиента, не в localStorage. Продление сессии
идёт через `/api/auth/telegram/refresh`, поэтому не зависит от сторонних cookies
в Telegram Web. Обычный браузер сохраняет прежние HttpOnly cookies. Эти два вида
refresh-сессий нельзя обменивать между адаптерами. SDK может сохранять параметры
запуска своим механизмом; приложение сохраняет в sessionStorage только признак
Telegram-вкладки, чтобы повторно загрузить SDK после обновления страницы.

Один Telegram связан только с одним аккаунтом и наоборот. В профиле доступно
отключение: удаляется привязка и отзываются Telegram refresh-сессии. JWT содержит
версию привязки, проверяемую на каждом запросе. Старый JWT сразу перестаёт работать,
в том числе после повторной привязки. Браузерный вход остаётся доступным.
Смена пароля отзывает уже выданные сессии всех клиентов; сама привязка сохраняется.
Если доступ к Telegram потерян, нужно отключить его в браузерном профиле.

Domain хранит связь и инварианты, Application описывает сценарии и порты,
Infrastructure проверяет криптографию и выполняет транзакции PostgreSQL,
API выдаёт JWT и проверяет доступ. Telegram SDK существует только во frontend.
Отдельный backend, polling-бот и Telegram-библиотеки для этого сценария не нужны.

## Публикация: что ещё требуется

1. Разместить приложение и PostgreSQL и получить публичный HTTPS URL.
   `localhost:5180` доступен только на компьютере разработчика.
2. В окружении сервера задать `Telegram__BotToken` и `Telegram__BotUsername`.
   Для Compose используются `TELEGRAM_BOT_TOKEN` и `TELEGRAM_BOT_USERNAME`
   в локальном файле окружения сервера. В Git секреты не добавлять.
3. В [BotFather](https://t.me/BotFather) выбрать бота → Bot Settings →
   Configure Mini App (Main Mini App) и задать HTTPS URL.
4. Через `/setmenubutton` выбрать этого бота, название кнопки «Открыть»
   и тот же HTTPS URL. Настройка токена сама не создаёт эту кнопку.
5. Открыть Mini App на телефоне и в Telegram Web/Desktop, привязать тестовый
   аккаунт, добавить расход, проверить его в браузере, отключить Telegram.

В nginx разрешено встраивание только с собственного origin и Telegram;
прежний `X-Frame-Options: DENY` блокировал бы Mini App в Telegram Web.
Кнопка «Назад» Telegram возвращает к обзору, интерфейс учитывает safe-area.
Обычные браузерные посещения не загружают Telegram SDK.

Автотесты используют искусственный токен. Интеграционные проверки покрывают
подпись, срок, неправильный пароль, общую историю, владение, конфликты привязки,
ротацию, отключение, повторную привязку и гонку отключения с refresh.
E2E с `E2E_TELEGRAM=true` проверяет адаптер с имитацией SDK и настоящим API,
настроенным **только** с искусственным тестовым токеном из CI. Это не заменяет
проверку реального Telegram-клиента после публикации.

Протокол проверки: [официальная документация Telegram](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app).
