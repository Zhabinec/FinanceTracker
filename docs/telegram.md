# Telegram Mini App

Telegram — основной способ входа в Finance Tracker. Бот открывает HTTPS-приложение внутри Telegram; финансовые запросы идут API приложения, а не Bot API.

Текущий бот: [PetProjectFinanceBot](https://t.me/PetProjectFinanceBot). Кнопка меню **Открыть** ведёт на https://finance-tracker-zhabinec.onrender.com/.

## Подключение бота

1. Создайте бота в [BotFather](https://t.me/BotFather) и сохраните токен в секретах.
2. Разместите frontend и API на публичном HTTPS-origin. localhost с другого устройства недоступен.
3. Задайте backend переменные Telegram__BotToken и Telegram__BotUsername без @.
4. Перезапустите сервис и проверьте GET /api/auth/telegram/options.
5. Через /setmenubutton в BotFather выберите бота, название **Открыть** и HTTPS URL.
6. Откройте кнопку в настоящем Telegram-клиенте и пройдите регистрацию.

Для профильной кнопки Main Mini App настройте Mini App отдельно в BotFather. Это дополнительный способ запуска; текущий опубликованный вход использует кнопку меню. Обычная ссылка на сайт не заменяет подписанный запуск.

Текущему приложению не нужны polling-процесс и webhook обработки сообщений: оно не читает переписку и не отправляет автоматические финансовые уведомления.

## Локальный токен

В корне репозитория:

~~~powershell
./scripts/configure-telegram.ps1
~~~

Скрипт поддерживает Windows PowerShell 5.1 и PowerShell 7. Он запрашивает токен скрыто, проверяет getMe и сохраняет Telegram:BotToken и Telegram:BotUsername в .NET User Secrets Finance.Api. Токен передаётся CLI через stdin и не печатается.

Скрипт не публикует сайт и не меняет меню бота. Для Docker отдельно задайте TELEGRAM_BOT_TOKEN в игнорируемом .env; User Secrets контейнер не читает. На Render используются Telegram__BotToken и Telegram__BotUsername.

При ошибке проверьте доступ к api.telegram.org и действительность токена. Не публикуйте полную HTTP-ошибку Bot API: URL содержит секрет.

## Первый вход

Пользователь нажимает **Начать в Telegram**. Сервер проверяет initData и атомарно создаёт пользователя без email, основной счёт, категории, привязку и сессию.

Повторная регистрация того же Telegram id возвращает тот же аккаунт. Простой запуск не создаёт аккаунт. Фиктивные email и известный пользователю пароль не генерируются.

Затем пользователь сохраняет финансовый код и может включить локальный PIN. Telegram-вход не передаёт серверу финансовый ключ и не заменяет разблокировку на новом устройстве.

## Прежний аккаунт

Для подтверждённого email-аккаунта откройте /login/password **внутри той же Mini App**. Форма проверяет email/пароль и подписанный initData, затем связывает Telegram с прежним user id.

Не создавайте сначала независимый новый аккаунт, если нужна прежняя история. Привязки не заменяются автоматически, истории не объединяются. Сведения о подключении доступны в разделе **Аккаунт**.

Telegram-only аккаунт не имеет самостоятельного email/Google-входа в браузере. Отключить его единственную привязку нельзя. Финансовый код не восстанавливает потерянный Telegram-аккаунт.

## Проверка личности и сессия

~~~text
Telegram SDK → исходный initData → API
  → HMAC-SHA256 и auth_date
  → серверная привязка
  → access JWT + refresh token
~~~

Срок initData — 10 минут, допуск будущего времени — 30 секунд. Клиентские id, username и initDataUnsafe не принимаются как доказательство личности.

Telegram refresh находится в памяти и продлевается через /api/auth/telegram/refresh, независимо от сторонних cookies Telegram Web. Его нельзя обменять на обычную браузерную refresh cookie.

В sessionStorage сохраняется признак Telegram-вкладки для повторной загрузки SDK; финансовый ключ туда не помещается.

Версия привязки проверяется в JWT. Отключение отзывает Telegram-сессии и прежние access tokens; повторное подключение не оживляет старую версию. Для email-аккаунта сохраняется браузерный вход.

## WebView и проверка

Интерфейс учитывает safe-area, имеет мобильную навигацию и использует Telegram BackButton для возврата к обзору. Google-кнопка в WebView скрыта. Заголовки framing должны разрешать Telegram, иначе Telegram Web может не открыть сайт.

Проверьте на телефоне и Desktop/Web: новый вход, повторный запуск, PIN, добавление расхода, восстановление с кодом и потерю связи.

Автотесты используют имитацию SDK и синтетический токен. Они не подтверждают меню BotFather и не заменяют реальную приёмку.

Протокол: [Telegram Mini Apps — validating data](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app).
