# Безопасная публикация исходников

Исходный код публичный; секреты не становятся безопасными после обфускации.
Токен Telegram, ключ Resend, JWT signing key и пароль Neon должны оставаться
в локальных User Secrets / игнорируемом окружении или Render Environment.
Расходы и доходы приватного аккаунта передаются серверу только в зашифрованном
документе; ограничения модели описаны в `decisions/private-financial-vault.md`.

## Проверка перед коммитом

В репозитории есть переносимый hook `scripts/git-hooks/pre-commit`.
Чтобы включить его только для текущего клона (не глобально):

```powershell
git config --local core.hooksPath scripts/git-hooks
```

Нужен официальный Gitleaks в PATH либо, для текущего Windows-клона,
`artifacts/security/gitleaks/gitleaks.exe`. В ходе проверки 27.10.2026
использована версия 8.30.1 из https://github.com/gitleaks/gitleaks/releases/tag/v8.30.1
с проверкой SHA256 по опубликованному списку checksum.
Бинарник и отчёты находятся в игнорируемой папке `artifacts/security` и не коммитятся.

Hook проверяет staged diff и блокирует локальный коммит с найденным секретом,
включая коммиты из GitHub Desktop. Он не устанавливается автоматически при clone.
Проверка дублируется в CI: полный fetch истории → проверка SHA256 бинарника →
Gitleaks по всем полученным refs. CI работает уже после push и сам по себе не
предотвращает первую публикацию секрета. Hook можно обойти; это защита от ошибок,
а не криптографическая гарантия отсутствия утечек.

`.gitleaks.toml` расширяет стандартные правила кодами восстановления FT1,
ключами Resend и паролями Neon. Разрешён только один точный литерал тестового
JWT в конкретном файле ApiFixture; каталог тестов целиком не исключён.
Не добавлять широкие allowlist или реальные секреты ради зелёной проверки.
Результаты сканера полностью маскируются, отчёты не публикуются артефактами CI.

## Что нельзя коммитить или отправлять в Docker build context

- заполненные `.env*`, `secrets.json`, локальные appsettings;
- ключи восстановления и экспорт финансов, в том числе зашифрованные копии;
- дампы БД, TLS/private keys и сертификаты с закрытыми ключами;
- трассы Playwright, скриншоты пользовательских данных и логи с секретами.

Примеры конфигурации остаются в Git с пустыми значениями секретов. Пароль
`finance_dev` и синтетические ключи CI предназначены только для локального
Docker / одноразовых тестов и не должны использоваться на публичном хостинге.

## Проверка 27.10.2026

Проверка истории Gitleaks сначала нашла фиксированный интеграционный JWT-ключ;
после точечного исключения этого тестового литерала сканирование чистое.
Проверка всех npm-зависимостей (включая dev) и NuGet с транзитивными пакетами не нашла
известных уязвимостей по ответам реестров на момент проверки.
Прямое сравнение трёх настроенных локальных секретов со всеми 53 доступными
коммитами также не нашло совпадений. Значения сравнивались локально через stdin,
без передачи в аргументах процессов и без вывода в отчёт.
Отдельно проверены владение приватным документом на backend, Telegram HMAC,
срок initData, Secure/HttpOnly refresh cookies и исключение секретов из конфигурации Git.
Это ограниченная проверка исходников и зависимостей, не внешний pentest и не
обещание защиты от всех атак. Короткий локальный PIN уязвимее длинного кода
при краже профиля браузера; старые дампы до переноса финансов остаются открытыми.

При обнаружении настоящего опубликованного секрета сначала отозвать/сменить его
у провайдера, затем убрать из файлов. Удаление строки новым коммитом не удаляет
секрет из старой истории. Перезапись истории и force-push требуют отдельного решения.
