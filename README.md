# Finance Tracker

Finance Tracker — приложение для личного учёта доходов и расходов в Telegram и браузере. Финансовая история шифруется на устройстве до отправки на сервер.

- [Открыть Telegram-бота](https://t.me/PetProjectFinanceBot) → меню **Открыть**.
- [Открыть браузерную версию](https://finance-tracker-zhabinec.onrender.com/).

Основной вход — Telegram без email и пароля. В обычном браузере доступен Google. Публичная регистрация по email отключена; тестовый Resend отправляет письма только владельцу своего аккаунта. Render и Neon используются как тестовый контур: после простоя первый запуск может быть медленным.

## Возможности

- Быстрое добавление дохода или расхода: категория → название → сумма.
- История с фильтрами, сортировкой, редактированием и удалением.
- Обзор доходов, расходов и результата периода; круговая диаграмма расходов появляется, когда есть данные.
- Собственные категории, счета, начальные остатки и переводы между счетами.
- Месячные бюджеты по расходным категориям.
- Импорт CSV/TSV с сопоставлением колонок и предпросмотром.
- Отображение сумм в RUB, USD и EUR по курсу без изменения исходных записей.
- Зашифрованная синхронизация, резервные копии и PIN для доверенного устройства.
- Адаптивный интерфейс с поддержкой клавиатуры и уменьшения движения.

Приложение не подключается к банкам и не выполняет платежи или реальный обмен валют. Excel-файл нужно предварительно сохранить как CSV.

## Первый вход

1. В Telegram нажмите **Начать в Telegram**; в обычном браузере выберите **Продолжить с Google**.
2. Сохраните код восстановления финансового хранилища.
3. Настройте шестизначный PIN на своём устройстве либо используйте только код.
4. Откройте **Категории**, выберите категорию и добавьте первую запись.

Вход в аккаунт и расшифровка истории — разные действия. На новом устройстве требуется код восстановления. Сброс пароля аккаунта не восстанавливает финансовый ключ. Отдельно созданные Telegram- и Google-аккаунты автоматически не объединяются.

Подробнее: [руководство пользователя](docs/user-guide.md), [модель шифрования](docs/decisions/private-financial-vault.md).

## Локальный запуск

Нужны .NET SDK 10, Node.js 24, PowerShell 7 и Docker с Linux containers. Команды выполняются из корня репозитория.

### Полное приложение в Docker

~~~powershell
pwsh -NoProfile -File scripts/init-local.ps1
docker compose build api
docker compose build frontend
docker compose up -d --no-build
docker compose ps -a
~~~

Скрипт создаёт локальный .env со случайным JWT-ключом и сохраняет существующие настройки. Сборки выполняются последовательно.

| Адрес | Назначение |
|---|---|
| http://localhost:5180 | Приложение |
| http://localhost:5180/register | Локальная регистрация с Mailpit |
| http://localhost:5180/login/password | Вход в существующий email-аккаунт |
| http://localhost:8025 | Тестовые письма Mailpit |
| http://localhost:5180/health | Проверка API и подключения к БД |

Для локального сценария зарегистрируйтесь, подтвердите адрес по письму в Mailpit и войдите по паролю. Внешним адресатам Mailpit письма не отправляет. Telegram и Google требуют отдельных настроек провайдеров.

PostgreSQL хранит данные в именованном томе. Обычные stop/start и down без удаления томов сохраняют базу. Подробные команды разработки, обновления и диагностики: [локальный запуск](docs/local-development.md).

## Технологии и репозиторий

Backend: ASP.NET Core / .NET 10, EF Core, PostgreSQL 17. Frontend: React, TypeScript, Vite, TanStack Query, React Hook Form и Zod. Криптография клиента: Web Crypto.

- backend/src/Finance.Api — HTTP, аутентификация и запуск приложения.
- backend/src/Finance.Application — сценарии и интерфейсы хранения.
- backend/src/Finance.Domain — серверные сущности и инварианты.
- backend/src/Finance.Infrastructure — PostgreSQL, миграции и внешние адаптеры.
- frontend/src/features — интерфейс и приватная финансовая модель.
- scripts — локальная настройка, backup и проверка восстановления.
- deploy — контейнерные конфигурации.

main — стабильная ветка; codex/platform-telegram — источник текущего Render-сервиса; codex/platform-web — отдельная платформенная ветка. Платформы используют общий backend.

Команды проверки приведены в [docs/testing.md](docs/testing.md). Настройка секрет-сканирования — в [docs/security.md](docs/security.md).
