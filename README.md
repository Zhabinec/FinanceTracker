# Finance Tracker

Учебное full-stack приложение для личного учёта доходов и расходов. Backend — ASP.NET Core / .NET 10, PostgreSQL и EF Core; frontend — React, TypeScript, Vite и TanStack Query.

## Возможности MVP

- Регистрация, вход, JWT, ротация refresh token и выход.
- Собственные категории доходов и расходов: создание, переименование, деактивация и восстановление.
- Создание, редактирование и удаление операций с проверкой владельца и версии записи.
- Фильтры по периоду, типу и категории; сортировка по дате и сумме; серверная пагинация.
- Dashboard: доходы, расходы, результат периода, распределение по категориям и последние операции.
- HTTP-ошибки, идентификатор запроса и структурированные серверные логи.
- Unit-, PostgreSQL integration- и браузерные тесты; конфигурация GitHub Actions.

Результат периода — доходы минус расходы. Отдельных счетов, начальных остатков, банковских интеграций и конвертации валют нет. Границы MVP определены в [PROJECT.md](PROJECT.md).

## Быстрый запуск в Docker

Нужен работающий Docker Engine с Linux containers. Выполните из корня репозитория:

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File scripts/init-local.ps1
docker compose up -d --build
docker compose ps
```

Скрипт создаёт игнорируемый Git файл `.env` со случайным JWT-ключом; существующий файл не перезаписывается. Можно вместо скрипта скопировать `.env.example` в `.env` и установить собственный случайный ключ длиной не меньше 32 байт.

Откройте **http://localhost:5180**, зарегистрируйте аккаунт и подтвердите email по письму в **http://localhost:8025** (Mailpit). В локальном режиме это имитация почты: внешним адресатам письма не отправляются. Проверка готовности всей цепочки: **http://localhost:5180/health**. Если порт занят, задайте `FRONTEND_PORT` в `.env` и повторите запуск.

Порядок запуска: PostgreSQL становится healthy → сервис `migrate` применяет EF Core migrations и завершается с кодом 0 → запускаются API и nginx. `docker compose ps -a` показывает в том числе завершившийся сервис миграций.

```powershell
docker compose logs --tail 100 api migrate
docker compose stop
docker compose start
```

Данные хранятся в именованном томе `finance_postgres_data`. Обычная остановка контейнеров сохраняет их. После обновления кода используйте `docker compose up -d --build`, чтобы применились миграции и новые образы.

Compose предназначен для **локальной демонстрации**: порты привязаны к loopback, PostgreSQL использует пароль разработки, frontend работает по HTTP. Для внешнего развёртывания нужны HTTPS на доверенном reverse proxy, `Auth__SecureCookies=true`, отдельные секреты БД/JWT и резервное копирование. Не публикуйте локальную конфигурацию напрямую в интернет.

## Локальная разработка

Нужны .NET SDK 10, Node.js 24, PowerShell 7 и PostgreSQL 17 (либо Docker).

1. Создайте `.env`, как описано выше, и запустите БД: `docker compose up -d postgres`.
2. Настройте ключ API через user-secrets:

```powershell
$financeKey = [Convert]::ToBase64String([System.Security.Cryptography.RandomNumberGenerator]::GetBytes(48))
dotnet user-secrets set 'Jwt:SigningKey' $financeKey --project backend/src/Finance.Api
```

3. Примените миграции и запустите API:

```powershell
dotnet tool restore
dotnet ef database update --project backend/src/Finance.Infrastructure --startup-project backend/src/Finance.Api
dotnet run --project backend/src/Finance.Api --launch-profile http
```

4. В другом терминале:

```powershell
cd frontend
npm ci
npm run dev
```

Frontend: http://localhost:5173. Vite проксирует `/api` на http://localhost:5280. Для одновременной работы с Docker-версией остановите её `api` и `frontend`, чтобы не путать окружения. База разработки настроена на порт 5433 в `appsettings.Development.json`.

OpenAPI в Development: http://localhost:5280/openapi/v1.json. JWT-ключ и production connection string не входят в репозиторий. `.env` читает Docker Compose; при `dotnet run` используйте user-secrets либо переменные окружения.

## Проверки

На рабочем компьютере запускайте проверки последовательно: дождитесь завершения
каждой команды перед следующей. Не совмещайте сборку Docker, .NET и браузерные
тесты. Для ограничения параллелизма MSBuild можно использовать
`dotnet build -m:1 -p:UseSharedCompilation=false` и затем
`dotnet test --no-build -m:1`. Пересборка Docker нужна при обновлении
контейнерной версии; для обычной разработки используйте локальный запуск выше.

```powershell
dotnet build
dotnet test
docker compose config --quiet
cd frontend
npm ci
npm test
npm run lint
npm run build
npx playwright install chromium
npm run test:e2e
```

Интеграционные тесты требуют Docker и создают отдельный временный PostgreSQL-контейнер. Они не используют БД приложения. E2E требует запущенного полного приложения на http://localhost:5180; для другого адреса задайте `E2E_BASE_URL`.

На Windows с ограниченным доступом к compiler server используйте `dotnet build -m:1 -p:UseSharedCompilation=false`; затем можно отдельно запустить `dotnet test --no-build`. Не запускайте две сборки одного checkout одновременно.

GitHub Actions запускает backend build/tests, frontend tests/lint/build и Docker + Chromium сценарий. Облачный запуск workflow появится после push в GitHub; локальные проверки не являются результатом GitHub Actions.

## Структура и контракт

| Слой | Ответственность |
|---|---|
| Finance.Api | HTTP, аутентификация, cookies, DI и обработка исключений |
| Finance.Application | Сценарии, DTO, валидация и интерфейсы хранения |
| Finance.Domain | Бизнес-инварианты без EF Core и ASP.NET Core |
| Finance.Infrastructure | EF Core, PostgreSQL и миграции |
| frontend/src/features | auth, categories, transactions, dashboard |

Основные endpoints:

- `POST /api/auth/register`, `/login`, `/refresh`, `/logout`; `GET /api/users/me`.
- `GET/POST /api/categories`; `PATCH /api/categories/{id}`; `POST /api/categories/{id}/deactivate` и `/restore`.
- `GET/POST /api/transactions`; `PUT /api/transactions/{id}`; `DELETE /api/transactions/{id}?version={version}`.
- `GET /api/dashboard?from=2026-10-01&to=2026-10-31`.

Список операций принимает `from`, `to` (обе даты включительно), `categoryId`, `type=Income|Expense`, `sort=dateDesc|dateAsc|amountDesc|amountAsc`, `page` и `pageSize` (1–100). Ответ: `{ items, totalCount, page, pageSize }`. Поддерживаются даты операций 1900–9998.

Суммы в ответах — строки, например `"123.45"`, чтобы сохранить точность в JavaScript. В БД — `numeric(18,2)`, в C# — `decimal`. `occurredOn` — календарная дата по Москве; техническое время хранится в UTC. Для изменения передайте `version`; устаревшая версия даёт `409`, после чего нужно перечитать запись. Удаление также требует версии.

Access token хранится в памяти браузера, refresh token — в HttpOnly cookie. В БД хранятся хеши refresh- и reset-токенов. Обычный выход отзывает refresh token; сброс пароля меняет security stamp и немедленно отзывает все старые access- и refresh-токены.

## Восстановление пароля

На странице входа доступна ссылка «Забыли пароль?». Локальный Compose доставляет письма в Mailpit: http://localhost:8025. Это тестовый почтовый ящик, внешним адресатам письма не отправляются. Ссылка действует 30 минут, используется один раз и передаёт токен во fragment URL, чтобы он не попадал в HTTP access logs.

Endpoints: `POST /api/auth/forgot-password` (`email`) и `POST /api/auth/reset-password` (`token`, `password`). Запрос восстановления возвращает одинаковое сообщение для известного и неизвестного email и ограничен по частоте. При недоступном почтовом сервисе сервер пишет безопасную ошибку доставки, а клиент по-прежнему получает общее сообщение.

Лимиты разделены по действию: запрос писем не расходует лимит самого сброса пароля. При исчерпании квоты API возвращает 429 Problem Details и Retry-After с оставшимся временем ожидания; интерфейс показывает причину вместо общей ошибки.

Письмо явно указывает email аккаунта и содержит HTML-кнопку и текстовую ссылку. Использованная или просроченная ссылка не активируется повторно: запросите новое письмо для своего адреса. Смена fragment-ссылки в той же вкладке обновляет токен формы. Автотесты удаляют только собственные созданные письма, чтобы использованные тестовые ссылки не засоряли ящик.

## Подтверждение email

Формат адреса проверяется при регистрации, а владение ящиком — одноразовой ссылкой подтверждения. До подтверждения правильный пароль не даёт access- или refresh-токен: API возвращает 403. Для подтверждения откройте письмо и нажмите «Подтвердить email». Срок ссылки — 24 часа. Повторная отправка доступна на `/verify-email` и не раскрывает наличие адреса в системе.

Endpoints: `POST /api/auth/confirm-email` (`token`), `POST /api/auth/resend-confirmation` (`email`). `GET /api/auth/email-delivery` сообщает интерфейсу, используется ли почтовая имитация. В Mailpit проверяется учебный сценарий доставки; подтверждение настоящего внешнего ящика требует настройки внешнего провайдера ниже.

После миграции ранее созданные аккаунты также должны подтвердить email: они намеренно не объявляются подтверждёнными автоматически. Запросите письмо на `/verify-email`; финансовые данные сохраняются.

Пароли копируются и вставляются нативным способом без удаления пробелов, Unicode и без усечения. Слишком длинный пароль отклоняется валидацией. Кнопка показа пароля позволяет проверить содержимое и скопировать его; повторный auto-repeat Ctrl/Cmd+V при удержании клавиш блокируется в редактируемых полях. Это не заменяет диагностику встроенного браузера при повторных событиях, не помеченных как auto-repeat.

Внешняя почта: настройте `Auth__FrontendUrl` на публичный HTTPS URL, `Email__Provider=Resend`, `Email__Endpoint=https://api.resend.com/emails`, `Email__From` на подтверждённый адрес/домен и `Email__ApiKey` через секреты окружения. Адаптер использует HTTP API без SDK; фактическая внешняя доставка требует аккаунта и настройки домена у провайдера. [API Resend](https://resend.com/docs/api-reference/emails/send-email).

Разбор решений и путь запроса: [docs/architecture.md](docs/architecture.md).

## Счета

### Быстрое добавление

На странице «Категории» нажмите активную категорию: откроется окно только
с названием и суммой. Например: «Продукты» → «Чипсы» → `25` → Enter.
Нажимать можно на всю плашку, включая её свободное место. Переименование,
отключение и восстановление находятся в отдельном меню «⋯». На узких экранах
категории расположены по две в ряд, кнопки управления имеют область 44×44 px,
а окно быстрого ввода располагается у нижнего края экрана.
Тип и категория подставляются, дата назначается сервером по Москве.
Основной или последний выбранный активный счёт подставляется автоматически;
при нескольких счетах его можно сменить в свёрнутом выборе. Имя и сумма
не теряются при ошибке. После сохранения есть «Отменить добавление».
Escape закрывает окно, фокус возвращается к категории; во время сохранения
закрытие и повторная отправка блокируются.

В `POST /api/transactions` поле `occurredOn` теперь необязательно: без него
используется московская дата того же серверного момента, что и `createdAtUtc`.
Явно переданная дата по-прежнему поддерживается полной формой журнала.
Отмена добавления использует обычное удаление с проверкой версии операции.

Страница `/accounts` позволяет создать счёт, переименовать, архивировать и
восстановить его. Валюта пока равна базовой валюте пользователя: другие валюты
появятся вместе с конвертацией. Начальный остаток задаётся один раз, допускает
отрицательное значение и не является доходом. Изменения после открытия
записываются финансовыми операциями.

Баланс — начальный остаток плюс доходы минус расходы, плюс входящие и минус
исходящие неотменённые переводы по всей записанной истории,
включая будущие даты. Это не баланс на выбранную дату. Он рассчитывается в БД,
а не хранится отдельным изменяемым числом. Архивный счёт сохраняет баланс и
историю; новые операции и перенос других операций на него запрещены.
Исторические операции можно исправлять и удалять, сохраняя тот же архивный счёт.

Миграция `AddAccounts` создаёт каждому существующему пользователю «Основной счёт»
с нулевым начальным остатком и переносит туда его операции без изменения сумм.
Новая регистрация создаёт такой счёт атомарно с пользователем.

Проверки среза счетов: 67 backend unit-тестов, 20 интеграционных тестов
(включая обновление БД со старой историей), 7 frontend-тестов. Браузерный
сценарий проверяет создание счёта, расход, исправление суммы, архивирование,
восстановление и возврат баланса после удаления операции.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/accounts` | Свои счета, включая архив, с балансами строкой |
| POST | `/api/accounts` | Создать: `name`, `openingBalance` строкой |
| PUT | `/api/accounts/{id}` | Изменить: `name`, `isArchived`, `version` |

Создание и редактирование операции принимают `accountId`; список операций
поддерживает одноимённый фильтр. Для совместимости старый запрос создания без
`accountId` использует основной счёт, а редактирование без него сохраняет текущий.
Если основной счёт архивирован, такой запрос создания отклоняется.
Переводы доступны на странице счетов в блоке «Перевод между счетами».
Нужны два своих активных счёта с одинаковой валютой. Сумма положительная,
с точностью до копеек; отрицательные остатки допустимы, как и для обычных операций.
Дата назначается сервером по Москве. Перевод не является доходом или расходом
и не попадает в dashboard и журнал доходов/расходов; у него отдельная история.

«Отменить перевод» убирает его влияние на оба баланса, сохраняя запись с отметкой
об отмене. Повторная отправка того же `requestId` возвращает существующий перевод;
иной состав данных с тем же идентификатором вызывает 409. Отменённая запись при
повторной отправке не восстанавливается. В форме идентификатор сохраняется для
повтора неизменённого запроса при потере ответа, до успешного завершения или
ухода со страницы; это не механизм восстановления черновика после перезапуска.

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/transfers` | `requestId`, `sourceAccountId`, `targetAccountId`, `amount` строкой, необязательный `description` |
| GET | `/api/transfers?page=1&pageSize=20` | Своя история, включая отменённые; максимум 100 записей на страницу |
| POST | `/api/transfers/{id}/cancel` | Отменить с текущей `version`; повторная отмена уже отменённой записи безопасна |

## Адаптивный интерфейс

Обзор, категории, операции, счета и аккаунт используют одну оболочку.
Пять пунктов навигации всегда сохраняют порядок и подсвечивают текущий раздел:
на ПК они находятся сверху, на телефоне и планшете — в закреплённой нижней панели.
Кнопка выхода — иконка с доступным названием и областью нажатия 44×44 px.

Итоги обзора видны перед настройками. Период раскрывается отдельно; в журнале
расширенная запись находится в «Запись с датой», а фильтры — в «Фильтры и
сортировка». На странице счетов создание раскрывается через «Новый счёт».
Основной быстрый ввод остаётся в категориях. Формы, карточки и меню проверяются
на 320, 390, 768 и 1280 px, включая раскрытые состояния и прокрутку.

Используются `100dvh`, `viewport-fit=cover` и отступы `safe-area-inset-*`.
Это базовая подготовка веб-интерфейса к мобильному WebView. Telegram SDK,
проверка initData и вход через Telegram ещё не подключены.

## Валюта отображения

Регистрация запрашивает только email и пароль. Новый аккаунт по умолчанию
использует RUB; поле `baseCurrency` в API пока поддерживается для совместимости
старых клиентов. Валюта существующих пользователей и их история не изменяются.

В обзоре, журнале и счетах можно выбрать RUB, USD или EUR. Предпочтение хранится
в браузере. Пересчитанные суммы отмечены `≈`: это справочное отображение по
последнему полученному курсу, не банковский обмен и не историческая оценка
на дату каждой операции. Рядом с заголовком — компактный переключатель RUB/USD/EUR. Формы ввода
и редактирования всегда используют исходную валюту; баланс и суммы в БД
не переписываются. Итоги и отдельные строки округляются независимо до копеек,
поэтому сумма округлённых строк может немного отличаться от округлённого итога.

`GET /api/currencies/rates` требует авторизации и возвращает дату, источник
и `rublesPerUnit` со значениями строкой. Сервер использует
[XML-сервис Банка России](https://www.cbr.ru/development/SXML/) и учитывает
номинал валюты. Курс кешируется в памяти на час; запрос ограничен 10 секундами
и 256 КБ. При ошибке нет скрытой подмены курса: API возвращает 503,
интерфейс показывает исходные суммы и предлагает повторить запрос.
Новых production-зависимостей и изменений схемы БД не требуется.

## Бюджеты и импорт

В «Обзоре» находятся месячные лимиты расходных категорий. Выберите месяц,
добавьте лимит и следите за потраченным, остатком и превышением. Учитывается
весь месяц по Москве, включая записанные будущие даты; переводы исключены.
Период финансового обзора и месяц бюджета выбираются независимо. Изменение
или удаление операции пересчитывает бюджет. Лимиты вводятся в базовой валюте;
переключатель валюты меняет только отображение сумм.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/budgets?month=2026-10-01` | Лимиты и фактические расходы текущего пользователя |
| POST | `/api/budgets` | `categoryId`, `month` (первое число), `limit` строкой |
| PUT | `/api/budgets/{id}` | Новый `limit` и текущая `version` |
| DELETE | `/api/budgets/{id}?version=…` | Удалить только лимит, сохранив операции |

В «Операциях» раскройте «Импорт из CSV». Доступен скачиваемый пример.
Файл — UTF-8 или Windows-1251, максимум 2 МБ, 1 000 000 символов, 1000 операций
и 50 колонок. Первая запись — заголовки. Разделитель: `;`, `,` или табуляция.
Поддерживаются кавычки, удвоенные кавычки и переносы внутри поля.

Выберите счёт и колонки даты, суммы, категории, при необходимости описания
и типа. Даты: `yyyy-MM-dd`, `dd.MM.yyyy`, `dd/MM/yyyy`; сумма положительная,
с точкой или запятой и максимум двумя десятичными знаками. Тип — `Income`/
`Доход` либо `Expense`/`Расход`; без колонки применяется выбранный общий тип.
Суммы не конвертируются, это значения в валюте выбранного счёта.
Названия категорий сопоставляются без учёта регистра внутри типа. Неизвестную
категорию нужно предварительно создать, неактивную — восстановить.

Предпросмотр ничего не сохраняет. Ошибки видны для каждой записи; хотя бы одна
ошибка блокирует весь импорт. Применение повторно валидирует файл и состояния
счёта/категорий, а затем одной транзакцией сохраняет все операции и отметку
импорта. Импорт влияет на историю, балансы, обзор и бюджеты.

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/imports/csv/preview` | Проверить и показать строки без сохранения |
| POST | `/api/imports/csv/apply` | Повторно проверить и атомарно применить файл |

Оба запроса: `content`, `delimiter`, `accountId`, `defaultType`, `mapping`.
Индексы в `mapping` начинаются с нуля: `date`, `amount`, `category` обязательны;
`description` и `type` допускают `null`. Для полей нужны разные колонки.

Защита повторного импорта использует SHA256 содержимого на пользователя:
BOM и окончания строк нормализуются, имя файла и выбранный счёт хеш не меняют.
Одновременное применение защищено уникальным индексом, повтор даёт 409.
Это защита повторного файла, а не сверка пересечений разных банковских выписок.
После потери ответа повторите предпросмотр: он покажет, был ли CSV сохранён.
Удаление импортированных операций не снимает отметку уже применённого файла.
Прямой XLSX пока не поддерживается: сохраните таблицу как CSV.

[docs/deployment.md](docs/deployment.md). Локальный compose остаётся демонстрационным;
отдельный production compose не публиковался на внешний сервер.
